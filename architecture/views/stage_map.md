# Stage map

One row per stage: who does the work, what it saves, and what check must pass before the next stage starts. Each agent uses its role's model chain (ADR-020). Full input and output contracts are in [contracts.md](contracts.md).

| # | Stage | Agent (model) | Artifact(s) | Check before moving on | Decided by | Job |
|---|---|---|---|---|---|---|
| 1 | Requirements | Requirements agent, with the adapted A1 skill (ADR-013) | `spec.json` (source), `spec.md` (rendered), attempt summary | the issue is not rejected as very vague (LLM verdict); `spec.json` matches its schema, and an LLM judge (never the requirements model) rates every acceptance criterion testable; on failure the agent gets one re-ask | script + LLM judge (logged as an LLM verdict) | Orchestrator |
| 2 | Design | Design + implementation agent, with `ARCHITECTURE.md` | `design.json` (source), `design.md` (rendered) | at most 10 targets; every target is `EXISTING` (file and symbol found by `ast`, including nested names and attributes, with a matching kind; non-Python files use kind `module`) or `NEW` (parent module exists); on failure the agent gets one re-ask | script | Orchestrator |
| 3 | Implementation | same agent, same conversation | `diff.patch` (made by script with `git diff`), attempt summary | package installs and imports; `ruff` passes; diff touches only design targets and tests, never `.github/`, configuration, lockfiles, `conftest.py` or `ARCHITECTURE.md`; existing test files unedited; runs with no secrets | script | Orchestrator |
| 4 | Testing | Testing agent, two phases in scratch copies (implementation unreadable in phase 1) | test files named `test_ac<n>_*`, `test_report.md` (made by script), attempt summary | no test fails that did not fail at baseline (failures re-run once); every AC has a passing `test_ac<n>_*` test that calls a design target with a non-trivial `assert` or `pytest.raises`; existing tests unchanged; no `conftest.py` added; phase 2 left every `assert` unchanged; runs with no secrets | script | Orchestrator |
| 5 | Release | none (script) | `pr.md` (four fields only), PR link | regex secret scan passes; base branch merges without conflict (ADR-021); branch has no foreign commits (never force-push); PR is open; `ci.yml` passes within 10 minutes, ignoring one known upstream collection error | script | Release |
| 6 | Review | Reviewer agent, model chain disjoint from code-writing roles, bash in a container holding only the PR commit (ADR-025) | `review.json` (source), `review.md` (rendered, posted as PR comment), label | every finding and approval cites a `file:line` that exists at PR HEAD, or a command the reviewer actually ran; an approval includes the reviewer's test command and is invalid if the job's test step fails beyond `baseline.json` or a finding is major or blocker; on failure the reviewer gets one re-ask | LLM verdict + script evidence check | Review |
| — | Route | none (script) | updated `state.json`, issue comment | verdict, classification and review round decide: human, re-entry or stop; records which job stopped | script | Route |

Retry caps (ADR-006, ADR-017): Stage 3 check fails → Stage 3 at most twice, then stop. Stage 4 check fails because of the code → Stage 3 at most twice, then Stage 2 once, then stop. Stage 4 check fails because of the tester's own files → Stage 4 once. A schema error, or a failed G1, G2 or G6, gets one re-ask. Any other failed check stops the run. At most two review rounds.

Re-runs (ADR-022, ADR-024): after a Release stop the next run starts at Stage 4; after a Review stop it skips Stages 1-4 and re-releases the same change for a new review. A manual `restart_from` (1-4) overrides both. Review findings are kept until their stage passes.

Budgets (ADR-023): step caps of 40 (requirements), 45 (design), 90 (implementation), 40 (testing) and 40 (review); 3M tokens per stage and 15M per run; command output kept to 10,000 characters.
